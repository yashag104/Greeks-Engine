Heston-COS AAD Greeks on FPGA

Viva prep for the Greeks Engine. The Heston price and all nine sensitivities come from one forward and reverse-mode AAD pass in fixed-point RTL, compared against bump-and-reprice on the same hardware. The numbers on this page come from the repository and from re-running verify_all.sh (21/21 pass) and pytest (20/20 pass) on 22 Sep 2026.

§0Is it ready to run on the board?

Not yet

It's verified bit-exact in simulation and ready for a first Vivado run, but not for the board. Vivado has never been run on it, there's no Zynq system around the core, and the ARM-side host code exists only as a Python spec.

§1The one-sentence claim

The price and all nine sensitivities come out of one forward and reverse-mode AAD pass in fixed-point FPGA hardware, using the COS Fourier method, compared head-to-head with bump-and-reprice on the same hardware. FPGA finance work has accelerated pricing (mostly Monte Carlo) or Greeks by bumping. This project puts AAD itself in hardware.

§3COS method (Fang & Oosterlee 2008)

V = e^(−rT) · Σ'_{k=0}^{N−1} Re[ φ(u_k) · e^(−i u_k a) ] · V_k u_k = kπ/(b − a), N = 128 V_k = 2K/(b − a) · (χ_k − ψ_k) Σ' : the k = 0 term is weighted ½ [a, b] = c1 ± 10√c2, c2 = v0·T + θT/2 (simplified cumulant)
  • χ and ψ are closed-form payoff integrals: the call is supported on [0, b], the put on [a, 0].
  • 10√c2 is computed as 8√c2 + 2√c2, two shifts and an add.
  • [a, b] is held fixed when differentiating. This is the standard COS convention and the software reference does the same. The Greeks are those of the COS approximation with the range frozen, and the difference from the true model Greeks shows up in the separately reported “method error”.
  • Why COS and not Monte Carlo: it's deterministic, needs no RNG, has a fixed trip count, and its terms are independent, which makes it a natural pipeline.

§4How AAD works in this design

Why reverse mode

Reverse mode gives every input's derivative for a small constant multiple of one evaluation, whatever the number of inputs (the cheap-gradient principle). Central-difference bumping needs 2n + 1 = 19 pricings for 9 inputs.

The structural insight: no global tape

The COS price is a sum of independent terms that share only per-evaluation constants. So the reverse sweep splits per term. Each term runs its forward pass and then its own adjoint sweep, and the per-term adjoints are accumulated. The tape is the pipeline's storage registers (443 register chains in z7h), which hold a term's forward values until its reverse sweep reads them.

Complex adjoints

For a holomorphic w = f(z), the adjoint is z̄ = conj(f′(z)) · w̄. That's why heston.py multiplies by P.conj(...) throughout.

term = Re(φ · e^(−iua)) · wV = (φr·cos ua + φi·sin ua) · wV seed = w̄_φ = wV · (cos ua, sin ua) φ = exp(e) ⇒ ē = conj(φ) · seed (wn_r, wn_i in heston.py, 2·WL-bit raw)

Adjoint normalization

At high k, |φ| ≈ 1e-5, so the raw adjoints would be only a few ULPs. The sweep is linear in the seed, so each term runs on seed·2s (s from adj_shift, the leading-one position of the raw pair, capped at FL) and every per-term output is shifted back by 2−s before accumulation. This was defect #8. It cut the ∂V/∂ρ error from 2.7e-5 relative.

Chain rule after the loop (finish step)

x = ln(S0/K) ⇒ ∂V/∂S0 = (∂V/∂x) / S0 V_k is linear in K ⇒ ∂V/∂K = (V − ∂V/∂x) / K disc = e^(−rT) ⇒ ∂V/∂r = disc·Σ∂/∂r − T·V , ∂V/∂T = disc·Σ∂/∂T − r·V

§6The precision bound

Each operation i produces vi + ei with |ei| ≤ εi·2−FL. To first order:

worst case : |Y_rtl − Y_exact| ≤ 2^(−FL) · Σ_i |∂Y/∂v_i| · ε_i typical 1σ : σ_Y ≈ 2^(−FL) · √( Σ_i (|∂Y/∂v_i| · ε_i)² / 3 ) (uniform on [−ε, ε] has variance ε²/3) bits lost : log₂( Σ_i |∂Y/∂v_i| · ε_i )
  • All ∂Y/∂vi come from one reverse sweep over the model graph (Graph.error_bound). That's AAD again (Linnainmaa 1976). The RTL's reverse sweep is part of the graph, so the same method bounds every Greek, not only the price.
  • Local ε: 0.5 ULP for every rounded multiply, shift or constant. The CORDIC outputs are given 2 ULP in ir.py.
  • Excluded, on purpose: second-order terms (O(2−2FL)), input quantization, overflow (checked separately), and COS method error (reported separately).
  • Measured error / bound ≤ 0.21 for the FSM engine and ≤ 0.115 for the generated designs, so the bound always holds. The 1σ estimate tracks the measured error, and the error falls as 2−FL over FL = 16…40.
  • AAD against bump in the same fixed-point format: bump error ≈ O(h²) truncation + O(ULP/h) cancellation, so the best h moves to 1e-2…1e-4. AAD beats the best h chosen per Greek by 5.6× to 690× (median about 220×), with no h to tune.

§7The generator: one description, four uses

eval_fixed

Bit-accurate integer emulator, the golden model the RTL must match.

eval_float

The same algorithm in double precision, the reference for hardware error.

error_bound

First-order bound and 1σ estimate for the price and every Greek.

sched + rtlgen

Modulo schedule over shared units, then synthesizable Verilog-2005.

Each node carries its own frac (fractional bits) and a width: W = WL, D = 2·WL (raw products), or B = 1 bit. Rounding is round-half-up everywhere. In Verilog: ((x >>> (s−1)) + 1) >>> 1.

§8The modulo schedule

Term k starts at S + k·II. A modulo reservation table ensures every term uses shared unit u at the same phase (t − S) mod II. II has a lower bound of max over resource classes of ⌈ops × busy / units⌉, then an ASAP list schedule is tried at that II and II is increased until it fits.

cycles = S + (N − 1)·II + L + F + 2 z7 (56-bit, 8 mul, iterative CORDIC): 113 + 127·32 + 506 + 46 + 2 = 4,731 z7h (setup/finish on the ARM) : 0 + 127·32 + 506 + 0 + 2 = 4,572 zu (64-bit, 32 mul, pipelined) : 113 + 127·8 + 423 + 45 + 2 = 1,599

Why 8 multipliers on the Zynq-7020 config

The iterative CORDIC takes FL + 4 = 32 cycles and is busy for all of them.

ResourceOps per termUnitsBound on II
CORDIC rotation3 × 32 cycles332

Multiplier251 × 1 cycle8⌈31.4⌉ = 32

All three constraints meet at II = 32. The price-only pricer has the same CORDIC work, so it is also stuck at II = 32 with its multipliers half idle. The AAD reverse sweep fills those idle slots, which is why the Greeks cost only 1.04 pricings (4,731 vs 4,565 cycles). The zu config pipelines its CORDICs (one new op per cycle), so it's multiplier-bound instead: 251/32 gives II = 8.

Storage chains

A glue register holds its value for II cycles, until the next term overwrites it. A term value consumed later than that is copied down a register chain of ⌈(life + 1)/II⌉ registers. These chains are the tape.

§9What the generated RTL looks like

  • t counts cycles from start and ph counts the term phase. Every glue node gets one register, written when ph equals its scheduled slot.
  • Accumulators acc_* are gated to the valid-term window. Pipeline fill and drain slots are ignored.
  • CORDIC runs FL + 2 iterations with 6 guard bits. Rotation mode folds |z| > π/2 by ±π and negates the result, and 1/K is pre-loaded into x. Vectoring handles x < 0 with ±π. The iterative version is one unit reused; the pipelined version has one stage per iteration.
  • All constants and ROM contents are emitted as integers by the same Python code the emulator uses, so the two agree by construction.
  • Narrow shifters and range_err: each data-dependent shift amount was measured over 150 random parameter sets and given only that range + 3. This cut LUTs from 90.6K to 59.0K. A sticky range_err flags any shift outside it. The ranges are empirical, not proven, and the flag is the safety net.
  • Host-setup (z7h): setup (77 mul) and finish (28 mul) move to the ARM. The FPGA takes 19 hs_* constants (see heston_aad_z7h_host.json) and returns 9 sums. LUTs drop from 59.0K to 45.5K with bit-identical results.
  • Bump wrapper: an FSM runs 19 sequential pricings on the price-only pricer, then computes (P⁺ − P⁻) · inv2h, with h and 1/(2h) supplied by the host, so there's no divider.

§11Limitations to state yourself

  • No Vivado results yet: Fmax, timing closure, power and energy are open.
  • Verified domain: S0 = 100, K ∈ [60, 150], T ∈ [0.1, 3], r ∈ [0, 0.1], v0, θ ∈ [0.005, 0.25], κ ∈ [0.2, 6], ξ ∈ [0.1, 1], ρ ∈ [−0.95, 0.6]. Outside it, range_err is raised. Scale S0 and K together for other spot levels.
  • [a, b] is held fixed when differentiating.
  • Shift ranges come from sampling, not proof.
  • No register sharing: every long-lived value has its own chain, which costs flip-flops.
  • The reverse sweep in heston.py is written by hand. What's automated is the error-bound sweep, the scheduling and the RTL generation.
  • Black-Scholes core is still at Q16.16 (price error ~5e-4).
  • Heston Monte-Carlo AAD (on-chip RNG, path-wise tape) is future work.

§12Likely viva questions

Where is the AAD tape in your hardware?

There's no global tape. The COS price is a sum of independent terms, so each term's reverse sweep needs only that term's forward values. Those are held in storage register chains in the pipeline (443 chains in z7h) until the sweep uses them.

Did the generator derive the adjoint code automatically?

No. The reverse sweep is written by hand as IR operations in heston.py and verified against independent references. The generator automates the error-bound reverse sweep, scheduling, binding and RTL. Automatic source transformation from the forward graph is a natural next step.

How do you know the RTL is correct?

Three links. (1) The RTL matches the fixed-point emulator bit-exactly at the register level for every setup and finish register, every register of terms 0–2, and all outputs, over 3–4 parameter sets. (2) The emulator's error against double precision always sits below a first-order bound, at ≤ 0.115 of it. (3) The double-precision code matches an independent reference: Richardson-extrapolated finite differences of a numpy COS implementation, and quadrature of the Fourier integral for method error.

Why is the error bound first order only? Is that rigorous?

Products of two rounding errors are O(2−2FL). At FL ≥ 20 every first-order bound is far below 1 ULP-scaled, so these terms are negligible. It is a linearized bound: rigorous to first order, not an interval-arithmetic guarantee.

Why is measured error only ~10% of the bound?

The worst-case bound assumes every rounding error has the sign that maximizes the output error. Real errors are roughly independent and partly cancel. The 1σ estimate, √(Σ(…)²/3), is the realistic prediction, and it matches the measurements.

Why 56-bit words on the Zynq-7020?

The repository doesn't record the reason, so prepare your own. By the estimate in sched.cost_estimate, 56 and 64 bits both need 12 DSP48E1 per multiplier, so DSPs are not the reason. The saving is in glue logic: every add, mux, register and shifter is 8 bits narrower, which is what gets the LUT/FF count to fit. FL = 28 still gives ~6e-7 price error and ≤ 6.4e-5 on the Greeks. 48-bit would give ~1e-5.

Why no dividers?

In the FSM engine, bit-serial dividers were 80% of the latency and dedicated area. Newton reciprocals turn a division into 6 multiplier uses, and those are shared resources the scheduler can place in idle slots. Each denominator is also inverted once and reused by the reverse sweep.

How is the 18× speedup fair?

Be upfront. The intrinsic work ratio is ~9.6× (2,413 vs 251 multiplies). 18× reflects this configuration: the pricer is CORDIC-bound with idle multipliers, and AAD fills them. At 4 multipliers the ratio is 10.1×. A throughput-oriented bump baseline could interleave the 19 bumped pricings to use the idle slots.

What is II and what sets it?

The initiation interval: cycles between the starts of consecutive terms. It is set by the most contended resource. On z7 the multipliers (251/8), CORDIC rotations (3 × 32 / 3) and vectorings (2 × 32 / 2) all give 32. On zu, with pipelined CORDICs, the multipliers set it: 251/32 gives 8.

What happens with inputs outside the verified domain?

A barrel shifter would receive a shift amount outside its measured range. The sticky range_err output is raised, and the AXI wrapper forwards it as m_axis_tuser. It's tested at T = 0.01. The result is flagged as invalid instead of being silently wrong.

Why hold [a, b] fixed? Doesn't that make the Greeks wrong?

It's the standard COS convention, and the software reference uses it too. The Greeks are exact derivatives of the COS approximation with a frozen range. Their distance from the true model Greeks is part of the method error, measured separately against Fourier-integral quadrature (fig2_accuracy_sweep).

What limits Fmax, and how would you fix it?

The single-register 56×56 multiply built from ~12 cascaded DSP48E1, the 113-bit rounding barrel shift plus increment in one stage, the CORDIC variable shift plus add, and 112-bit leading-one detection. The fix is more pipeline stages in the multiplier and shifter. The scheduler already takes the latency as a parameter; rtlgen.py would need to emit the extra stages. Bit-exactness doesn't change, only cycle counts.

Why move setup and finish to the ARM?

They run once per evaluation (77 + 28 multiplies) but cost dedicated glue logic. Moving them cut LUTs from 59.0K to 45.5K, which is what makes the design fit the 7020. host.py is the bit-exact spec, and host + FPGA equals the on-chip design exactly. A C port for the ARM still has to be written.

What did the precision audit of the FSM engine find?

Eleven defects. Headline ones: every constant truncated to 16 fractional bits (φ(0) = 0.999977); an exp using floor instead of round in range reduction; the outer COS loop at Q16.16 (price 0.8% high); the complex divide forming |b|² unscaled; floor rounding giving a −0.5 ULP bias per op summed over 128 terms; low-frequency cancellation in complex sqrt; a behavioral “/” that would synthesize a huge divider.

Why is AAD more accurate than bump-and-reprice in fixed point?

Bump error is truncation O(h²) plus cancellation O(ULP/h). In fixed point the ULP is large, so the best h moves up to 1e-2…1e-4 and the error floor rises to 5e-7…5.5e-5. AAD has no h. Its error is just the propagated rounding, 9e-10…1.6e-6: 5.6× to 690× better than the best h chosen per Greek.

How are ∂V/∂S0 and ∂V/∂K obtained without adjoints for S0 and K?

S0 and K enter the loop only through x = ln(S0/K) and the linear factor K in Vk. So ∂V/∂S0 = (∂V/∂x)/S0 and ∂V/∂K = (V − ∂V/∂x)/K, both computed in the finish step.

How do you handle complex numbers in reverse mode?

For holomorphic w = f(z), the adjoint is z̄ = conj(f′(z)) · w̄. Every complex multiply in the reverse sweep uses the conjugate of the forward partial. The seed of φ is wV·(cos ua, sin ua), from differentiating Re(φ·e−iua).

Why is adjoint normalization exact?

The per-term sweep is linear in its seed. Scaling the seed by 2s and scaling the outputs by 2−s gives the same mathematical result. In fixed point it moves the values up into the well-resolved range, so the same rounding costs far fewer relative bits. The scaling is a power of two, so it's a shift.
